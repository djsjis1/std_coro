# 第 1 讲：协程基础概念

## 核心要点

- **协程是一个"可以暂停、之后恢复"的函数**：它记住了自己执行到哪一行。
- C++20 协程是**无栈（stackless）协程**：暂停时局部变量不留在调用栈上，而是移到一个独立的"协程帧"里。
- 一个函数只要出现了 `co_await`、`co_yield`、`co_return` 三个关键字之一，它就是协程。
- 协程**不创建新线程**：暂停时它根本不消耗任何线程；恢复时才需要一个线程来继续执行。
- 协程的价值是**用同步的写法表达异步的流程**，而不是"让代码并行变快"。

---

## 1.1 从一个日常比喻开始

想象你在读一本书。读到一半，你放下书去接了个电话，回来之后**接着刚才那一页继续读**。

普通函数做不到这一点：它要么一口气执行完，要么被 `return` 彻底终结。它没有"暂停"这个概念。

协程就是那个"能夹书签的函数"。它的特殊能力是：

1. **暂停（suspend）**：执行到某个点，停下，把"当前状态"保存起来，把控制权交还给调用者/调度者。
2. **恢复（resume）**：将来某个时刻，从暂停点**下一行**继续执行，仿佛从未离开。

用伪代码表达，普通函数的调用是这样的：

```
调用者 → [函数执行……执行完毕] → 返回调用者
```

协程的调用是这样的：

```
调用者 → [执行一部分] → 暂停 → 回到调用者（或别人）
        ...一段时间过去...
        某个"调度者" → 恢复 → [继续执行剩余部分] → 完成
```

关键差异：**协程在暂停和恢复之间，调用它的那条线程可以做别的事情。**

## 1.2 协程解决什么问题

### 问题 A：回调地狱

假设你要"读取文件，然后处理，然后写入结果"三步异步操作。传统回调写法：

```cpp
void process_file(const std::string& path) {
    async_read(path, [](std::string content) {          // 第 1 步
        auto result = transform(content);               // 第 2 步
        async_write(path + ".out", result, [](bool ok) { // 第 3 步
            if (!ok) log_error();
        });
    });
}
```

每多一步异步操作，就多一层缩进；错误处理、循环、条件分支全都变得支离破碎。

协程写法（概念性示例，后续章节给出可编译版本）：

```cpp
// 同样是三步异步操作，看起来却像同步代码
task<void> process_file(const std::string& path) {
    std::string content = co_await async_read(path);   // 暂停直到读完成
    auto result = transform(content);                  // 正常写逻辑
    bool ok = co_await async_write(path + ".out", result);
    if (!ok) log_error();
}
```

`co_await` 的意思是："发起这个异步操作；如果它还没完成，就暂停我，**等它完成后再恢复我**。" 写法是顺序的，执行却是异步的。

### 问题 B：状态机爆炸

没有协程时，表达"分步执行"的状态可以用状态机：

```cpp
enum class State { Connect, Send, Receive, Done };
State s = State::Connect;
while (s != State::Done) {
    switch (s) {
    case State::Connect: /* 尝试连接... */ s = State::Send; break;
    case State::Send:    /* 发送... */     s = State::Receive; break;
    case State::Receive: /* 接收... */     s = State::Done; break;
    }
}
```

协程把这个状态机**自动生成**了——编译器把协程函数编译成一个状态机，你只写顺序代码。

## 1.3 C++20 协程是无栈协程

这是本讲最重要的概念，务必理解。

### 有栈协程（stackful）

早期协程（如 boost::context、Go 的 goroutine 的思路）会给每个协程分配**独立的调用栈**。暂停协程时，整个栈原样保留（占用内存）；恢复时切回这个栈。

```
线程 A（有栈协程）:
┌──────────────┐     ┌──────────────┐
│  协程1 的栈  │ ... │  协程2 的栈  │    每个协程常驻一块栈内存
│  (常驻内存)  │     │  (常驻内存)  │
└──────────────┘     └──────────────┘
```

### 无栈协程（stackless）——C++20 的选择

C++20 协程**不拥有独立调用栈**。协程暂停时，它需要的局部变量被复制到一个名为**协程帧（coroutine frame）**的结构体里（通常在堆上分配），协程自己的执行栈就"结束"了——它不再占用任何线程栈空间。

```
暂停前:                         暂停后:
┌─线程调用栈────────────┐      ┌─线程调用栈────────────┐
│ 协程的局部变量...      │      │  (协程已经"退场")     │
│ 正在执行中            │      │  线程可以干别的事      │
└───────────────────────┘      └───────────────────────┘
                               ┌─堆上的协程帧──────────┐
                               │ 局部变量副本           │
                               │ 暂停点(状态机状态)      │
                               └───────────────────────┘
```

由此带来两个重要推论：

1. **暂停不占线程**：一百万个暂停中的协程，可以只由一条线程驱动（这正是事件循环模型的基础，见第 11、12 讲）。
2. **帧是分配在堆上的**：这是 C++20 协程的固有成本（第 13 讲会讨论如何优化它）。

> 注意区分：Go 的 goroutine、Lua 的协程是"有栈"；Python 的 `async def`、JavaScript 的 `async`、C++20 协程都是"无栈"。有栈协程可以在任意深度的嵌套调用中暂停；无栈协程的暂停点必须显式写出（`co_await`），因此也更可控、更高效。

## 1.4 三个关键字：判断"这是不是协程"

C++20 中，判断一个函数是不是协程只有一条规则：

> **函数体内出现了 `co_await`、`co_yield` 或 `co_return` 中的任意一个，它就是协程。**

| 关键字 | 作用 | 典型场景 |
|---|---|---|
| `co_await` | 等待一个异步操作，可能暂停 | 异步 IO、等待任务 |
| `co_yield` | 产出一个值并暂停 | 生成器、惰性序列 |
| `co_return` | 返回最终结果，协程结束 | 协程正常完成 |

三个关键字的约束：

- 协程**不能用普通 `return`** 返回值（写了 `co_` 关键字之后，`return;` 只能写空返回，且很少用）。
- `main()` 函数不能是协程。
- 协程的**返回类型必须是满足要求的类类型**（第 2 讲详解）。

### 一个最小协程长什么样

先直观感受一下，细节第 2 讲解释：

```cpp
#include <coroutine>
#include <iostream>

// 一个最简单的协程返回类型（第 2 讲详解每行的含义）
struct my_coro {
    struct promise_type {
        my_coro get_return_object() { return {}; }
        std::suspend_never initial_suspend() { return {}; }
        std::suspend_never final_suspend() noexcept { return {}; }
        void return_void() {}
        void unhandled_exception() {}
    };
};

my_coro say_hello() {          // ← 因为有 co_return，这是一个协程
    std::cout << "Hello, ";
    co_return;                 // 协程在此结束
}

int main() {
    say_hello();               // 创建并"执行"协程
}
// 输出: Hello,
```

你也许注意到：这个协程**没有暂停**，它只是"换了种方式写函数"。真正有意思的是加入 `co_await` 之后，函数能够"停在中间"。这就是下一讲的主题。

## 1.5 协程与线程的关系（最重要的心智模型）

很多初学者误以为"协程 = 轻量级线程"。请记住：

- **协程是函数，线程是执行载体。** 协程暂停时释放线程；恢复时需要某条线程来跑它。
- 线程由操作系统调度（抢占式）；协程由**代码显式控制**何时暂停、何时恢复（协作式）。
- 一条线程上可以顺序驱动成千上万个协程（单线程事件循环模型）。
- 多个协程也可以在**多线程**上运行，但同步问题需要另行设计（`std::mutex` 等）。

用一个时间轴图来表示单线程上的三个协程如何"并发"：

```
时间 →
线程:   [协程A] [协程B] [协程C] [协程A] [协程C] ...
        ─────── ─────── ─────── ─────── ───────
         A 暂停   B 暂停   C 暂停   A 完成   C 恢复
         (等IO)  (等定时器)(等IO)   ↑        ↑
```

它们从未同时运行，但因为等待期间线程被让出来了，整体吞吐量远高于串行阻塞。

## 1.7 小结

1. 协程 = 可暂停可恢复的函数，暂停点由 `co_await` / `co_yield` 显式标记。
2. C++20 协程是无栈协程：暂停时状态存入堆上的协程帧，不占用线程栈。
3. 协程不创建线程；它把"异步逻辑"写成"同步形状"。
4. 一个函数含 `co_await` / `co_yield` / `co_return` 之一即协程，编译器会为它生成状态机。
